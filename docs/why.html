Why this exists

Because repetitive form HTML is expensive.

This project exists to reduce boilerplate when field definitions are already known as data. If the schema exists, the UI can be generated from it instead of hand-coded repeatedly.

The problem

  • Repeated HTML for similar fields
  • Duplicated wrappers and layout code
  • Manual glue between schema and UI
  • Slow iteration when form definitions change

The idea

  • Keep the form definition in structured data
  • Render from that schema
  • Keep behavior lean and predictable
  • Use config for layout and theme, not app logic

One-sentence summary

The repo exists to turn structured form metadata into working DOM forms with minimal boilerplate.
